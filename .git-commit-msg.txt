Restructure p2p_customization into approval_engine as settlement/vendor_portal modules

Moves settlement/ and vendor_portal/ from the separate p2p_customization
app package into approval_engine's own package, per the frappe-app-dev
skill's one-app/multiple-modules convention. Rewrites every dotted import
path, hooks.py target, DocType/Workspace module field, JS namespace
reference, and copyright header accordingly; merges both apps' hooks.py
(doc_events, scheduler_events, permissions, doctype_js, website hooks)
and patches.txt/modules.txt.

Comments out required_apps = ["jfs_report_customization"] (kept
required_apps = ["erpnext"] active, since erpnext is genuinely required
by settlement's Purchase Order/Invoice/Supplier customizations and is
available in this bench) to avoid a migration failure on sites without
jfs_report_customization installed. Code paths touching "JFS Settings"
will still fail at runtime until that app is available and this line is
restored.

Also carries over two independent fixes discovered while testing
bench migrate on an earlier pass of this merge:

- All of settlement's FAQ/KYC patches moved from pre_model_sync to
  post_model_sync, and a new create_settlement_custom_fields_early patch
  added first -- create_faq_master's FAQ Master.after_insert cascade
  (sync_supplier_custom_field -> rebuild_web_form_faq_fields) saves the
  vendor-onboarding-form Web Form, which needs the Settlement module and
  Supplier custom fields to already exist; neither is true during
  pre_model_sync on a from-scratch install.
- Added the missing Nature of Service Reference child doctype (Supplier's
  "nature_of_service" Table MultiSelect field pointed at it, but it was
  never committed to the original p2p_customization source).
